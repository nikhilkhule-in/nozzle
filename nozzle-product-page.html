Nozzle is a workflow engine that owns three things: the order steps run in, the data that flows between them, and the truth about whether it worked. How you write it, where it runs and who does the work stay yours.

The engine’s promises hold in every environment.

Laptop, cluster or edge, dev or prod, the semantics of a run are identical. Nothing below depends on where you deploy.

A graph you can trust

The workflow is validated before anything runs. Cycles, unknown dependencies and impossible references are rejected in plain language within a second, not nine minutes into a build.

Failure stays local
A failed step blocks only what depends on it and says why. Independent branches keep going, and the exit code is zero only if every step made it.

   

  
Data rides the graph
A step’s output reaches every step that needs it. Small values arrive as environment variables, so the image tag from step one is simply $IMAGE_TAG in step two. Large ones, like datasets and checkpoints, travel as blobs by reference. If a value can’t be passed safely, the step fails loudly instead of truncating it.

   
IMAGE_TAG=reg/app:4f2a9cblob://model.ckpt
error: build output can’t be passed safely, so the step failed instead of truncating it

  
Retries with memory
Attempts are tracked and bounded, with backoff. Leases and heartbeats mean a lost worker loses nothing, and retried work resumes where the schedule left off.

   
backoffbackoff

  
Gates, conditions and events
Conditional steps are skipped honestly, never silently. A gate suspends the run until a human answers. Every lifecycle move is an event, so any run can be replayed exactly.

   
claimedstartedretriedsucceeded

  
One workflow, every environment
Dev, staging and prod run the same file. Steps are local processes on a laptop and containers in prod, prod adds an approval gate, and ordering, data flow and failure semantics stay identical in all three.

 

 

  
Schedule it
Add a cron line to the same file. No separate scheduler to keep alive.

  
Watch it
The web console listens to the lifecycle stream, so live states, logs and retries never go stale.

  
Replay it
A run is its event stream. Replay any run to debug it or show a teammate what happened.

  
Generate clients
One HTTP contract defines the engine, so clients generate themselves in any language.
